Current browser setup: 1280×800, DPR 1, SVG 892×695, initial camera `0 0 2 1`, natural + hillshade at 0.55 opacity. The existing renderer chooses z from projected pixels, 256/512-pixel tiles, three workers **per layer**, three shared server detail slots, eight cached physical halo tiles, 64 MiB encoded memory cache and 512 MiB encoded disk cache. Browser cache retains 192 reusable entries plus pinned visible children/parents.

The source trace confirms that all three editors use TileSurface; geometry/visibleViewport use the same letterboxed coordinate transform. Parent images sort before children. Terrain is sampled from a common authoritative surface/procedural function; no new procedural surface is selected by LOD. Strict revision requests and active-request guards are present.

The remaining reproducible presentation defect is independent publication: after the first two zoom gestures, base natural terrain has complete z2 coverage, but hillshade lacks z2 coverage at 10 sampled screen positions **while the footer says Ready**, after network idle. See `baseline/old-01-zoom.png` and recorded layer states. Only the base TileSurface receives onLoading; the shading instance's state and failure are invisible to the status UI. Children of both layers also publish individually, so mixed-resolution rectangular regions are exposed during loading. A controlled held shading child and deeper camera sequence are recorded by `tests/viewport-baseline.mjs`.

Commit all required raster layers from one complete camera/revision transaction. This addresses demonstrated partial and independently completed presentation; it is not evidence that the authoritative sampler needs replacing. Compare shared sample positions and imagery before adoption. Do not decrease source resolution or raise concurrency.
